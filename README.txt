NSTU MEET — учебная платформа НГТУ
=================================

Что есть в этой версии
----------------------
- Только НГТУ в регистрации и профилях; вуз обязателен и указывается честно.
- Страна, факультет и курс используются для учебной навигации.
- Аккаунты, анкеты, лайки, чаты, группы, объявления, лекции и статусы Premium хранятся в общей серверной базе через SQLAlchemy.
- Поддерживается PostgreSQL через DATABASE_URL. Локально используется SQLite для разработки.
- Стабильные пароли с хешированием и постоянная серверная сессия.
- Фото профиля и медиа чата; объявления с кнопкой «Написать продавцу»; поиск по объявлениям.
- Портал лекций: факультет, курс, преподаватель, предмет, публикация PDF/PPT/PPTX/изображений.
- Бесплатный аккаунт может выбрать до трёх предметов; Premium получает доступ ко всем предметам и может публиковать учебные материалы.
- Premium-группы, просмотр лайков и лимит лайков.
- Светлый адаптивный интерфейс и анимации с учётом prefers-reduced-motion.
- Базовая обработка входящих уведомлений ЮMoney: Premium активируется только после валидного серверного уведомления, не от возврата в браузер.

ВАЖНО: перед использованием на Render
-------------------------------------
1. Сначала создай PostgreSQL в Render Dashboard.
2. В настройках веб-сервиса добавь переменную DATABASE_URL со значением Internal Database URL созданной PostgreSQL. При первом старте приложение создаст таблицы.
3. Старые данные из прежней SQLite-базы автоматически в PostgreSQL не переносятся. Перед переключением надо сделать экспорт/резервную копию старой базы и отдельно перенести пользователей/объявления, если файл базы ещё доступен. Не удаляй старую базу до проверки.
4. Для загруженных файлов создай Persistent Disk в Render, mount path: /var/data. В проекте UPLOAD_DIR задан как /var/data/uploads. Без постоянного диска загруженные фото и лекции могут исчезнуть после пересоздания контейнера. Persistent Disk может быть платным и ограничивает горизонтальное масштабирование.
5. Сохрани SECRET_KEY как стабильную случайную строку в Render Environment. Не публикуй .env, DATABASE_URL, пароль базы или платёжные секреты в GitHub.
6. Проверь, что Render подключён к ветке main и Auto-Deploy стоит On Commit или After CI Checks Pass при настроенных CI-проверках.
7. После настройки базы/диска сделай deploy, проверь Logs, регистрацию нового тестового аккаунта, выход/вход, профиль, публикацию объявления, чат и загрузку/скачивание лекции.

ЮMoney и Premium
----------------
- В этой версии настроен сценарий разового платежа через YooMoney Quickpay с суммой 360 ₽ за 30 дней. Для работы администратор должен установить YOOMONEY_RECEIVER и YOOMONEY_NOTIFICATION_SECRET в Render Environment, а также указать публичный адрес сайта.
- В настройках YooMoney нужно включить/настроить уведомления на POST /payments/yoomoney/notify и использовать тот же секрет уведомлений. Уведомление проверяется подписью, а Premium не активируется по простому переходу на страницу возврата.
- Это НЕ автоматическое ежемесячное списание. Пользователь оплачивает очередной период отдельным платежом. Для автопродления нужен отдельный платёжный продукт/договор, который явно поддерживает рекуррентные платежи, согласие пользователя и отмену подписки; не считайте это реализованным в текущей версии.
- До настройки и тестирования платёжного кабинета не рекламируй оплату как работающую.

Безопасность и ограничения
--------------------------
- Сервис предназначен для пользователей 18+.
- Университет указан по само-декларации, это не проверка студенческого статуса.
- Загружай только файлы, на которые имеешь право. Ограничения формата/размера есть, но перед широкой публикацией нужны антивирусная проверка файлов, CSRF-защита, rate limits, полноценная модерация, политика конфиденциальности и резервные копии.
- Доступ к чатам после взаимного лайка; написать продавцу можно через объявление. Блокировка отключает переписку между участниками.
- Бесплатный пользователь может выбрать три предмета. Если пользователь переключает предметы, список выбранных предметов в этой версии пока не имеет интерфейса снятия выбора; администратор может очистить выбор в базе. Это можно добавить следующим улучшением.

Локальный запуск Windows
------------------------
1. Установи Python 3.11+.
2. Распакуй архив и открой папку, где лежат app.py, requirements.txt, templates и static.
3. В командной строке выполни:
   py -m venv .venv
   .venv\\Scripts\\activate
   pip install -r requirements.txt
   py app.py
4. Открой http://127.0.0.1:5000.

Обновление через GitHub
-----------------------
1. Распакуй архив.
2. Открой папку nstu_meet внутри архива и загрузи её содержимое в корень существующего GitHub-репозитория через Add file → Upload files.
3. Подтверди замену совпадающих файлов и нажми Commit changes.
4. Дождись Deploy на Render.
5. ВАЖНО: до переключения на PostgreSQL сохрани старую SQLite-базу, если она ещё доступна. Переключение DATABASE_URL само по себе не переносит старые аккаунты и объявления.
